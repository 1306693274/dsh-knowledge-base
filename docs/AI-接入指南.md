# 给 AI 的接入指南：把本机的规则 / 知识 / 技能 / 插件 / 路由显示到这个面板

> 读者是 AI 助手，不是人。读完后你要做的是**改配置让插件去读本机文件**，不是把内容搬进插件。
> 本文件也可在线取：`GET /plugins/dsh-knowledge-base/guide`（`curl -f` 拿全文，适合你直接读完执行）。
>
> 版本 0.22.0｜适用于 dsh-knowledge-base ≥ 0.21.0

## 0. 这个插件的硬事实（先记住，后面全建立在它上面）

| 事实 | 含义 |
|---|---|
| **不存正文** | 面板显示的就是磁盘上那份文件，改就是改原文件（带历史快照可回退）。库目录 `~/.dsh/知识库/` 只有索引缓存、历史、布局、分类覆盖，**没有知识副本**。 |
| **只读扫描 + 就地编辑** | 面板不改你的目录结构；它按配置去扫，扫不到就是空列表。 |
| **五类归属** | `general` / `design` / `dynamic` / `assistant` / `finance`，可增删（见第 2 步）。 |
| **找不到不等于坏** | 任何一段缺失都只导致对应视图为空并给提示，不会崩。所以「看起来空」永远是配置问题。 |

## 1. 四步接入（每步都有完成判据）

### 第 1 步：探测本机真实结构，不要猜路径

```bash
curl -fsS http://127.0.0.1:<DSH端口>/plugins/dsh-knowledge-base/status
```

看 `data.roots`（`dsh` / `pkg` / `work`）与 `data.warnings`：

- `roots` 指向真实存在的目录、`warnings` 为空 → 这一步已完成，跳到第 2 步。
- `warnings` 里出现「pkg 根为空 / 工作区路径不存在」→ 必须第 2 步配 `知识库.json`，否则规则、Agent 目录全扫不到。

**判据**：`status` 的 `warnings` 是空数组。

### 第 2 步：写 `~/.dsh/知识库/知识库.json`（唯一必做项）

这是「去哪读」的总开关。没有这个文件时插件用内置默认表（那份表是作者机器的目录命名），装到别的机器上大概率扫不到东西。

```json
{
  "roots": {
    "dsh": "C:\\Users\\you\\.dsh",
    "pkg": "E:\\同步盘\\...\\deepseek",
    "work": "E:\\你的工作区"
  },
  "sources": [
    { "cat": "general", "group": "全局指令", "root": "dsh", "path": "AGENTS.md" },
    { "cat": "general", "group": "全局技能", "root": "dsh", "path": "skills", "dir": true, "only": "SKILL.md" },
    { "cat": "general", "group": "规则", "root": "pkg", "path": "rules", "dir": true },
    { "cat": "design", "group": "根目录规则与流程", "root": "work", "path": "design-agent", "dirOnly": true },
    { "cat": "design", "group": "技能", "root": "work", "path": "design-agent/skills", "dir": true, "only": "SKILL.md" }
  ]
}
```

字段语义（**只有这些**，多余的键会被忽略）：

| 字段 | 必填 | 取值 | 说明 |
|---|---|---|---|
| `cat` | 是 | `general` / `design` / `dynamic` / `assistant` / `finance` | 归到哪个分类；不写按 `general` |
| `group` | 否 | 任意短文本 | 列表里的分组标题，缺省「其他」 |
| `root` | 是 | `dsh` / `pkg` / `work` | 相对哪个根；根来自上面的 `roots` |
| `path` | 二选一 | 相对路径 | 单个文件或目录 |
| `paths` | 二选一 | 字符串数组 | 多个路径合并到同一个 `group` |
| `dir` | 否 | `true` | 递归收该目录下所有 `.md` |
| `dirOnly` | 否 | `true` | **只收该目录第一层**的 `.md`（不递归）——用于「Agent 根目录那一堆规则，但不含子目录」 |
| `only` | 否 | 文件名，如 `SKILL.md` | 只收这个文件名；**技能必须写这个**，否则技能正文会被当普通文档收进来 |

硬规则：

1. `root` 只能是那三个键；写绝对路径进 `path` 会被当相对路径拼错。
2. 收 `.md` 为主；`only` 用来收 `SKILL.md` 这类固定名。
3. 一个物理目录**只配一次**，否则重复条目（同一文件出现两次）。
4. 不要把 `node_modules` / 备份目录 / `.venv` 配进来，扫描有 8000 文件上限。

**判据**：`GET /index?force=1` 的 `data.items` 非空，且 `data.counts` 里每个分类都跟你预期一致；`data.warnings` 仍为空。

### 第 3 步（可选）：分类表 `~/.dsh/知识库/分类.json`

只在这两种情况下改：① 你要改分类名（比如「设计 Agent」→「平面设计」）；② 你要**新增一类 Agent**。

```json
{
  "_defaultsVersion": 2,
  "categories": [
    { "id": "general", "label": "通用" },
    { "id": "design", "label": "设计 Agent" }
  ],
  "keywords": {
    "design": "平面|设计|版式|配色|PSD|海报|详情页|主图|AI 生图",
    "finance": "交易|投研|行情|A股|财报|量化|回测|策略"
  }
}
```

- `keywords` 是**正则源字符串**，`|` 分隔，**顺序即优先级**（先匹配到的赢）；每条匹配用 `\b` 之类的词边界包一下，避免 `EAC` 命中 `reach`。
- `_defaultsVersion`：插件内置默认表的版本号；这个值**小于**内置版本时，插件会重写你的文件以带进新的默认分类。你手动改过就别动它，或先备份。
- 覆盖判据：文件属于哪一类**先看文件名**（`inferCat`），再看目录；都不中落 `general`。
- 单份文件判错时**不要改分类表**，用面板里的分类下拉（写进 `分类覆盖.json`，按文件 id 覆盖），或直接调 `POST /override {id, cat}`。

**新增一类 Agent 要动四处**（少一处就会有孤立节点）：

1. `分类.json` 的 `categories` 加一条 `{id, label}`；
2. `分类.json` 的 `keywords` 加这条 id 的正则；
3. `sources` 里把该 Agent 的目录配上 `cat: <新id>`；
4. `AGENTS.md` 的开工索引表加一行领域判据（见第 4 步），并在 `09-路由\` 下建对应路由文件。

**判据**：`/index` 的 `data.categories` 出现新分类，且 `data.counts[新id] > 0`。

### 第 4 步（可选）：路由线——让画布画出一跳、二跳

画布的路由线来自 `~/.dsh/AGENTS.md` 里的一张表。**表头必须包含这五个字**：`这件事一出现`（插件按这五个字定位表，找不到就只画文件和分类，不画路由线）。

```markdown
| 这件事一出现，就去读 | 读哪份（先读这层路由，再由它指到正本） |
|---|---|
| **先判领域，再查对应的那份** | 下面是领域判据，不是关键词表 |
| **平面视觉类**：跟图、改图、版式、色调、AI 生图 | `$PKG\routes\design.md` |
| **其余都算通用** | `$PKG\routes\general.md` |
```

解析规则（照做才解析得到）：

- 只认**表格行**，行首是 `|`；空行即表结束。
- 第一格 = 触发条件（展示用，去掉 `**` 与反引号）。
- 第二格 = 目标：**反引号包住的路径才算**（`` `a\b\c.md` ``）；一格可以多个。
- 二跳由路由文件自己那张表再写一遍同样的格式，`09-路由\X-路由.md` 里的行会显示成「第二跳」。

**判据**：`GET /routes` 的 `data.count > 0`；`GET /canvas` 的 `data.edges` 里有 `kind: "route"`。

### 第 5 步（可选）：插件节点——让插件挂到归属文档下面

插件不是独立文件，它从「插件归属」类文档的**表格**里抽出来。要让它抽得到，文档必须长成这样：

```markdown
## 三、本 Agent 独占的插件

| 插件 / 包 | 装在哪 | 干什么 |
|---|---|---|
| `image-gen` | `<工作区>\tools\dsh-image-gen.js` | 提供 generate_image 生图工具（banana / gemini 两个引擎） |
| `design-workbench` | link `<工作区>\tools\dsh-design-workbench` | 设计工作台面板（图库 / 画布标注 / 批量任务） |
```

抽取规则（不满足就抽不出来）：

| 规则 | 细节 |
|---|---|
| 小节标题必须命中 | `独占的插件` / `MCP 连接` / `本地插件文件` / `全局已装的插件包` / `靠全局插件` |
| 小节标题不能含 | `技能` / `工具` / `怎么核` / `怎么改` / `不独占`（这些小节里的表格不会被当插件） |
| 第一格必须是反引号包的名字 | `` `mcp-photoshop` ``；纯文字、带空格、以数字开头都不算 |
| 第一格含「技能」二字 | 跳过（当技能，不当插件） |
| 说明列怎么选 | 在各列里挑**长度 6–200 字、含中文、不含路径分隔符 `\`、不以 `<` 开头、不含 `: ` 或 `={ `** 的那一格；4 列取第 3 列，3 列第 3 列太短（≤10 字）时取第 2 列 |
| 同一插件出现在多份文档 | 合并成一个节点，说明取**更长**的那句 |

文件名要求：文档名里要出现 `插件清单` / `插件与工具归属` / `插件归属总表` 之一，否则类型不会被标成「插件」。

**判据**：`GET /index` 的 `data.plugins` 非空；`/canvas` 里 `kind: "plugin"` 的边存在，且 `from` 是该归属文档的节点 id。

## 2. 状态四色（判据与阈值）

每个文件条目一个空心圈，含义固定，**界面只允许这四种颜色**：

| 圈 | 判据（满足即停，从上往下） |
|---|---|
| 🔴 红 | AGENTS.md 字节数 > `65536`（`agent-instructions` 的 maxBytes，超了尾部被截断）；或 SKILL.md 的 `description` > `500` 字 |
| 🟠 橙 | 字符数 > `12000` |
| ⚪ 灰（虚线） | 没被引用：不在路由目标里、不在路由文件正文里、不在阀门 `entries` 里、也没被任何其它已收录文档正文点名 |
| 🟢 绿 | 其余（≤12000 字且用得上） |

阈值写死在插件常量里（`HEAVY_CHARS` / `HARD_AGENTS_BYTES` / `HARD_SKILL_DESC`），改不了也没必要改。
你要做的是**让红圈变绿**：拆长文档、把技能 `description` 压到 500 字内。

## 3. 必须跑的四条校验（全绿才算接完）

全部加 `-f`（不加时 403/404 也算成功）：

```bash
B=http://127.0.0.1:<DSH端口>/plugins/dsh-knowledge-base
curl -fsS $B/status        # roots 真实、warnings 为 []
curl -fsS "$B/index?force=1"   # items 非空；counts 每类符合预期；每条 chars>0
curl -fsS $B/canvas        # ok:true；有 kind:"cat" 节点；rows>0 才有 route 边
curl -fsS $B/routes        # count>0；没有表时 warning 里写明缺哪张表
```

## 4. 失败对照表

| 症状 | 原因 | 改哪里 |
|---|---|---|
| 列表空的，`counts` 全 0 | `sources` 没配或 `path` 写错（相对根） | 第 2 步；对照 `status.roots` 逐条核 |
| 只有通用有东西，Agent 分类全 0 | `sources` 里只有 pkg 的条目 | 给每个 Agent 目录补 `cat` + `root: work` |
| 同一文件出现两次 | 同一目录配了两条（或 `dir` 与 `dirOnly` 重复配） | 合并成一条 |
| 技能列表里全是技能正文 | 技能目录没写 `only: "SKILL.md"` | 补 `only` |
| 画布没有路由线，`/routes` 给 warning | AGENTS.md 没有含 `这件事一出现` 的表头 | 第 4 步 |
| 画布有「未入库」灰点 | 路由指向的文件没被任何 `source` 收录 | 把该目录加进 `sources` |
| 插件节点一个都没有 | 小节标题不匹配，或第一格没用反引号 | 第 5 步的抽取规则表 |
| 分类看着不对（文件归错类） | 文件名没命中关键词 | 用面板分类下拉覆盖，别改 `keywords` 硬凑 |
| 顶部黄条「工作区路径不存在」 | `roots.work` 写错或盘符变了 | 改 `知识库.json` |

## 5. 不要做（会破坏这个面板的前提）

1. **不要把文档复制进 `~/.dsh/知识库/`**：那里只放索引/历史/布局/覆盖；正文要在原位。
2. **不要手改** `~/.dsh/知识库/history/`、`画布布局.json`、`分类覆盖.json` 之外的文件；历史是回退用的，动了就没法退。
3. **不要用面板改插件配置**：面板只能改 `.md` 正文与路由表；插件装卸走 `plugin_manager`，插件配置改预设 patch。
4. **不要给同一含义加第二套视觉**：图例里有几个颜色，界面上就只能出现几个；加第二个圈或第五种颜色会被自检判红。
5. **不要写死盘符**：路径一律经 `roots` 解析，换机器只改配置。
6. **不要为了「显示得好看」改文件名**：分类与类型都从文件名推断，改名会连带改变归类与收录层（规则层/参考层）。

- [ ] `/routes` 的 `count > 0`（你写了开工索引表的话）
